# Project Memory

## Project Overview
GleamClient (formerly Orion Client), a client-only Fabric mod for Minecraft 1.21.11, 26.1.2, 26.2 and 26.3. The 1.21.11 artifact targets Java 21; 26.x targets Java 25. The private worktree uses Stonecutter 0.9.8 for versioned builds. Git origin remains `https://github.com/zarplayka/OrionClient.git`; source packages and asset namespace remain `ru.orion.client` / `orion-client`. Sources and Git history are authoritative for current branding.

## Project Structure
- `src/main/java/ru/orion/client/`: client initialization, configuration, GUI, HUD, effects and mixins.
- `src/main/resources/`: mod metadata and assets.
- `native/media/`: Windows media helpers, built during resource processing.
- `src/main/resources/assets/orion-client/html/hud-island/`: current HTML/CSS/JavaScript HUD island and media player.
- `src/main/java/ru/orion/client/media/OrionMediaPlayerHud.java`: Lumen view, native-pixel mouse forwarding from ChatScreen and JSON state/action bridge.
- `src/main/java/ru/orion/client/media/OrionMediaController.java`: asynchronous media polling and commands through Windows helpers.
- `media/GleamLyrics.java`, `GleamLyricsService.java`, `GleamAudioBeatMonitor.java`: timed lyric parsing, asynchronous LRCLIB lookup and cache, and a reader for the Windows audio analyzer.
- `media/{GleamWorldLyrics,GleamLyricsMesh,GleamLyricsTimeline}.java`: world-space lyrics, extruded vector glyphs, animation and cue navigation. `config/GleamLyricsSettings.java` stores its settings under `animatedLyrics`. The media island displays lookup status only.
- `src/main/java/ru/orion/client/discord/OrionDiscordPresenceService.java`: Discord IPC handshake and SET_ACTIVITY payload.
- `tests/manual/OrionMediaSeekTest.cjs`: Node regression tests executing the real HUD script with a minimal DOM and controlled clock.
- `sources/`: external reference sources; do not modify.
- `AGENTS.md`: project development and rendering instructions.
- `effect/GleamBetterHitReg.java`, `effect/GleamHitFeedbackTracker.java`, `mixin/GleamHitReg*.java`: immediate cosmetic hit feedback and duplicate matching.
- `artwork/better-hit-reg/{source.png,icon-64.png,README.md}`: generated detailed diamond-sword icon, actual packed image and exact imagegen prompt/provenance.
- `tests/manual/GleamHitRegIconGenerator.java`: deterministic source-image resizing and packing into only module atlas cell 63.
- `artwork/pets/`: standalone Blockbench Modded Entity projects for three Minecraft Java cosmetic pets, with embedded textures and animation keyframes.

- `settings.gradle`, `stonecutter.gradle`, `versions/<minecraft>/gradle.properties`: supported targets, controller tasks and per-version dependencies; common client build logic stays in `build.gradle`.
- `render/GleamGpu.java`, `GleamPose.java`, `GleamLumenVertex.java`: typed compatibility bridges for GPU pipelines, world transforms and Lumen vertex attributes.
- `tests/manual/GleamMixinAudit.java`: ASM-based audit of registered injection methods and INVOKE sites, integrated into each target's `check`.

## Architecture & Technical Decisions
- 1.21.11 basketball now delegates first-person hands to engine/GleamBasketballHands, using cached native PLAYER/PLAYER_SLIM ModelParts and sleeve children. Arm length stays 12/16 blocks, with reachable wrists and bounded far targets. Dribble projection maps the world ball through the captured world matrices into the actual hand projection/model-view/pose, including sprint FOV and bobbing. The held offset is shared by rendering and OrionBasketballController.helper39, preventing a different ball origin on release. The existing manual renderer and held offsets remain on 26.x.
- Legacy sports/glint rendering: before canceling ItemInHandRenderer.renderHandsWithItems on 1.21.11/26.1, flush feature submissions and end the main buffer batch; vanilla normally does this inside the canceled method. The short submitModel overload's final integer is outlineColor on every supported version, not tintedColor: zero prevents the goalkeeper becoming a white mask. For 1.21.11 custom glint, preserve cached FoilType and apply None only at draw time. Custom GLINT passes need their own fixed buffers after base geometry; the shared buffer flushes too early for EQUAL depth. BufferSource gets a private mutable copy of its ordered map only when needed, only this client's custom glint types are registered, and owned native buffers close on CLIENT_STOPPING.
- Item Scroller access is centralized in `effect/GleamItemScrollerServers` and `OrionItemScroller.isServerAllowed()`. Trusted network domain boundaries are exact/suffix matched. A daemon refreshes known game-host A/AAAA/SRV endpoints every five minutes; literal IP connections require matching resolved IP and port. Unknown virtual host names sharing an allowed proxy IP remain denied. Menu catalog, search, favorites, toggles, settings, scroll and Shift-drag honor the policy; saved config remains unchanged. Decisions are cached per address/socket/DNS snapshot and the HTML bridge reacts to catalog membership changes.
- Mirage on 26.2 must run immediately after LevelRenderer.render and before clearDepthTexture. A hook before renderItemInHand is already too late. The mixin audit enforces this ordering, and actual GPU readbacks verified visible SSR output.
- AGENTS.md describes the established Java2D UI pipeline: cache images, fingerprint all visual state and preserve exact texture/blit scale. After the fetched Gleam updates, some UI, including the media HUD, uses HTML/CSS/JavaScript rendered through OrionLumenView / LumenNative instead; preserve the actual owning implementation.
- Configuration setters save changes through OrionConfigManager.
- Current ClickGUI first uses OrionSiteMenu/Lumen with `html/menu/{index.html,style.css,preview.js,game.js}` and Java-exported siteCatalog/siteState. `renderImage()` exercises a legacy fallback with a different appearance. Current theme IDs are 3/4; legacy IDs 0/1/2 sanitize to 3.
- BetterHitReg uses a bounded 64-swing, one-second tracker, monotonic nanoTime and entity reference identity; per-target 475ms spacing prevents animation restart on spam. Do not gate prediction on delayed server damageCooldownTime. State clears on disabling, level/player replacement or presence of external betterhitreg. Only direct confirmed local PLAYER_ATTACK feedback is deduplicated. Existing server confirmation handlers remain intact.
- Verify actual Minecraft signatures from the Loom jars when needed.
- Media controller polls every 900 ms and publishes extrapolated position rounded to 0.2 seconds; the HTML HUD interpolates between updates with performance.now(). Helper commands run on a separate bounded executor and may complete after stale snapshots arrive.
- Seek preview must survive pointer release until a matching position is reported. The HUD holds a pending seek for up to 8 seconds, resets it on errors/session or track changes, and handles expiry even without incoming snapshots. Album participates in track identity. Drag calculations read current track geometry to handle scale/layout changes.
- Discord large image now defaults to the existing GleamClient badge hosted at an immutable GitHub raw URL for commit `33e1c06b1a357eda560481818831532a342fc16b`. `sanitize()` migrates the old `orion_icon` key and empty values to this URL while preserving custom image settings. This avoids the old Discord asset's baked-in Orion Client text without editing external reference sources or uploading new art.

- Private multiversion build: Stonecutter targets 1.21.11 / Fabric API 0.141.6+1.21.11, 26.1.2 / 0.155.3+26.1.2, 26.2 / 0.161.0+26.2 and 26.3 / 0.164.0+26.3 share source/resources through version conditions. 1.21.11 uses official mappings and net.fabricmc.fabric-loom-remap, Java 21 bytecode, remapJar/remapSourcesJar; 26.x uses the unobfuscated Loom plugin, Java 25 and jar/sourcesJar. Never distribute the 1.21.11 development JAR. Java 25, Gradle 9.6.0, Loader 0.19.5 and Loom 1.17.21 remain pinned. Ordinary root `build` builds and audits all targets independently of the active source version. Release/source outputs are collected into root `build/libs`, with `mc26.2` / `mc26.3` filenames. The compatibility alias `gleamclient.jar` always means 26.3. `build/supported-versions.json` describes verified artifacts.
- Compiler annotation ABI is pinned to Fabric Mixin 0.17.3 through mixin_compile_version for Loader 0.19.3 / MixinExtras 0.5.4 compatibility. Runtime libraries still follow the launcher. The integrated audit rejects array-encoded Redirect.at.
- Only the root builds native media helpers. All version resource tasks depend on it; their packaged binaries and source kits retain reproducibility verification. ASM/Gson used by the mixin audit are isolated build-tool dependencies and are not added to the mod.

## Implemented Features
Animated Lyrics is an optional section of the existing MediaPlayer settings. It draws extruded 3D text in Minecraft using world depth, timed LRCLIB documents, four typography styles, configurable offset, true word reveal when the source supplies word timings, and audio response from the Windows render endpoint. Sky places large lines above the horizon and Floating places smaller lines near the camera. Follow View is optional and off by default, so a phrase remains in world space once placed. Plain lyrics and unavailable tracks have explicit states in the media island. Both MediaPlayer and Animated Lyrics need to be enabled.

BetterHitReg is an optional Combat module (default off): locally predicts vanilla hurt animation and attack/hurt sounds, immediately at default Hitreg=0 ms or after the selected 0–200 ms delay, and suppresses matched repeats. Its settings gear opens a single Hitreg slider. Actual server damage, health, knockback and network latency are unaffected. New classes have the Gleam prefix.

Existing project includes HUD, ClickGUI, world effects, media integration and Discord RPC; inspect owning sources before changing behavior. Fetched GleamClient 0.2.3 includes HTML interfaces, accounts/chat updates, sports and rendering improvements. Media seeking now immediately updates its display for both pointer and keyboard controls, suppressing stale-position rollback. Discord activity explicitly sends `name: GleamClient` in addition to the existing branded details and image tooltip.

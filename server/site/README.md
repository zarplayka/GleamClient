# API аккаунтов GleamClient

`app.py` разворачивается в `/opt/orion-site/app.py`. Доверенные origin задаются переменными `ORION_SITE_ORIGIN` и `ORION_SITE_ADDITIONAL_ORIGINS`.

В production основной origin — `https://gleamclient.xyz`. Сервис `orion-site.service` слушает `127.0.0.1:8088` на `153.51.172.5` и хранит аккаунты в `/var/lib/orion-site/site.db`. Для параметров интеграций предусмотрен `/etc/orion-site/site.env`. Ежедневные снимки SQLite хранятся в `/var/lib/orion-site/backups`.

Новый сайт передаёт `/api/*` через Caddy на существующий сервис без подмены браузерного Origin. POST требует заголовок `X-Orion-Request: 1`, защищённые операции — также CSRF-токен из ответа сессии. Авторизация использует Secure/HttpOnly/SameSite=Strict cookie `__Host-orion_session` сроком до семи суток. Пароли и токены не хранятся в localStorage.

Фронтенд использует `/api/me`, `/api/login`, `/api/register`, `/api/logout` и `/api/email`. При регистрации на новом сайте требуется email. Существующие пользователи могут добавить или поменять его в профиле, указав текущий пароль. Привязка Minecraft, покупки и заявки Plus не включены в новый интерфейс.

## Почта и восстановление пароля

Яндекс Почта используется через SMTP с TLS на порту 465. Сервис читает адрес отправителя из `ORION_SITE_MAIL_FROM`, доверенный HTTPS-адрес для ссылок из `ORION_SITE_MAIL_ORIGIN` и пароль приложения из файла `ORION_SITE_MAIL_PASSWORD_FILE`. В systemd пароль передаётся через `LoadCredential`. Секрет хранится отдельно от исходников.

Подтверждение запрашивается через `/api/email/verify/request` из профиля и автоматически при регистрации или сохранении неподтверждённого адреса. Подтверждение действует сутки. Сброс через `/api/password/reset/request` доступен для подтверждённых адресов, но сам ответ о приёме запроса одинаков для любого корректного адреса. Ссылка на сброс действует 30 минут. Оба вида ссылок одноразовые. После сброса старые сессии завершаются.

## Проверки

Для подтверждения контактов зарегистрируйте приложение Discord и OAuth App GitHub. В поле redirect URL укажите `https://gleamclient.xyz/api/profile/oauth/discord/callback` и `https://gleamclient.xyz/api/profile/oauth/github/callback` соответственно. Установите `ORION_SOCIAL_ORIGIN` в HTTPS-адрес сайта из списка доверенных origin. Для каждого сервиса задайте `ORION_DISCORD_CLIENT_ID` или `ORION_GITHUB_CLIENT_ID` и путь к файлу секрета в `ORION_DISCORD_SECRET_FILE` или `ORION_GITHUB_SECRET_FILE`. Секреты можно передавать через `LoadCredential`, как пароль приложения для почты.

Контакты подтверждаются только после входа в Orion. Сервер сохраняет идентификатор и имя внешнего профиля. Токены провайдера используются для одного запроса профиля и не сохраняются. Имена, введённые до появления привязки, остаются видны владельцу в настройках и публикуются после подтверждения.

`test_site.py` запускается в окружении с существующим aiohttp: `python -m unittest -v test_site`. Проверки создают отдельную временную SQLite-базу. Не направляйте тесты на production-базу. Они покрывают оба разрешённых origin, отклонение посторонних origin, обязательный служебный заголовок, регистрацию, вход, восстановление сессии, атрибуты cookie, CSRF, выход, повторный ник, неверный пароль и ограничение регистрации.

Сценарий восстановления проверяет подтверждение почты, одинаковый ответ для неподтверждённого и неизвестного адреса, одноразовость ссылки и завершение старых сессий. В тестах отправка писем заменена записью вызовов.

## Продажи Plus через FunPay

В админ-панели создайте промокод для существующего аккаунта GleamClient, укажите скидку, долю автора и запас ключей на тариф. Сайт применит скидку к рублёвым ценам Plus, покажет расчёт и поставит четыре лота в очередь. Автор получает ссылки на опубликованные лоты и статистику в «Моих промокодах». Покупатель активирует ключ из заказа в своём профиле.

Ключ из опубликованного лота активируется сразу после ввода. Бот отдельно привязывает заказ к ключу, учитывает продажу и применяет возвраты. Доля считается от рублёвой суммы, которую FunPay возвращает в деталях заказа. Дополнительные расходы, включая комиссию вывода, отдельно не вычитаются. Для выплаты учитываются подтверждённые заказы. Перевод выполняется вручную, после чего Owner записывает его в админке. Полный возврат отзывает доступ по ключам заказа. Если долю уже перечислили, корректировка уменьшает будущий баланс. Частичный возврат требует указать итоговую сумму заказа в админке.

Для запуска нужен отдельный процесс Python 3.12+ с библиотеками `requests>=2.32.4,<3`, `requests-toolbelt>=1,<2`, `beautifulsoup4>=4.13,<5` и `lxml>=5.3,<8`. Добавьте в `PYTHONPATH` корень checkout [FunPayCardinal](https://github.com/sidor0912/FunPayCardinal/tree/c09dd13be25072bb3d5cdbba33d1e0d70e477710) на ревизии `c09dd13be25072bb3d5cdbba33d1e0d70e477710`. Запускается только `python funpay_worker.py`, остальные компоненты Cardinal для этой интеграции не требуются.

- `GLEAM_FUNPAY_SITE_ORIGIN` — HTTPS-адрес сайта, который сервер принимает в заголовке Origin.
- `GLEAM_FUNPAY_TOKEN_FILE` — файл со случайным токеном длиной от 32 символов. Одинаковое значение у сайта и бота.
- `GLEAM_FUNPAY_ACCOUNT_KEY_FILE` — защищённый файл с ключом сессии продавца. Читает только бот.
- `GLEAM_FUNPAY_SESSION_STATE_FILE` — путь внутри приватной папки бота, где он сохраняет обновлённую сессию между перезапусками. После замены исходного ключа бот начинает с новой сессии.
- `GLEAM_FUNPAY_NODE_ID` — идентификатор рублёвой категории FunPay с автовыдачей. Перед публикацией проверьте, что категория подходит для этого товара.
- `GLEAM_FUNPAY_SERVER_ID` и `GLEAM_FUNPAY_PRODUCT_TYPE` — значения полей сервера и типа товара в форме раздела, если FunPay требует их выбрать.

Бот передаёт ключи штатной автовыдаче FunPay и сверяет их с заказами продавца. При однозначном отказе FunPay лот можно поставить в очередь повторно. При потере ответа бот ищет предложение по названию, сроку и промокоду. Если подходящего лота нет, очередь оставляет его на сверке, чтобы повторный POST не опубликовал дубликат. Запас ключей задаётся при публикации. Автоматическое пополнение существующего лота пока отсутствует.

Сценарии начислений, одноразовых ключей и возвратов проверяются в отдельной SQLite-базе командой `python -m unittest -v test_funpay`. Перед первым запуском для покупателей сверяются реальный заказ, его сумма, статус и ключ, возвращённый FunPay продавцу.
